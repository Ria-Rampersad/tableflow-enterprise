# Automation (n8n)

`n8n/` — 8 importable workflow files (generated by `scripts/build_n8n_workflows.py`):
01 failed payments · 02 failed POS integrations · 03 new order processing · 04 loyalty point updates ·
05 daily financial reconciliation (06:00 SAST) · 06 low-stock notifications · 07 incident escalation · 08 daily management report.

## Run in n8n (Docker)
```bash
docker compose up -d n8n
docker compose --profile setup run --rm n8n-import     # imports all files (inactive)
```
Open http://localhost:5678, create the owner account, then activate the workflows. Environment variables used by
the workflows are set on the `n8n` service in `docker-compose.yml` (`TABLEFLOW_API_URL`, `TABLEFLOW_CLIENT_ID`,
`TABLEFLOW_CLIENT_SECRET`, `ALERT_WEBHOOK_URL`, `ALERT_TOKEN`); `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` lets `$env` work.
TableFlow sends events to `http://n8n:5678/webhook/<path>` (`N8N_WEBHOOK_BASE_URL`). Alerts go to TableFlow's local
alert sink unless you set a Slack/Teams incoming-webhook URL.

## Run without n8n (local demonstration)
`local-runner/n8n-local-runner.mjs` executes the same JSON files for the node types they use (webhook, schedule,
HTTP Request, IF, Code, Wait [skipped], NoOp). It is **not** n8n. With the API running:
```bash
bash scripts/run_n8n_workflows_locally.sh
```
